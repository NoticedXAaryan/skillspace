# SkillSpace Future Implementation Plan

**Vision:** Build the Expo of AI capabilities — a platform where discovering, installing, running, and sharing AI skills feels as effortless as `npx expo start`.

**Inspiration pillars (from Expo):**
1. **Zero-friction DX** — `expo start` just works. No config, no boilerplate.
2. **Unified CLI ↔ Dashboard** — every CLI action reflects on the dashboard instantly, and vice versa.
3. **Community flywheel** — EAS build, Expo Go, plugin ecosystem, showcases — the community builds on the platform and the platform surfaces community work.

---

## Current State Summary

| Area | Status |
|---|---|
| CLI (21 commands) | Functional — run, install, publish, init, search, agent, mcp, workflow |
| Registry Web App (27+ pages) | Functional — landing, packages, dashboard, playground, analytics, profile, settings |
| Runtime Engine | Functional — 4 model adapters, MCP, firewall, sandbox, permissions |
| Database (24 Prisma models) | Functional — users, packages, versions, orgs, collections, reviews, discussions |
| Design System | Sharp Dark aesthetic, shadcn/ui, Tailwind, CSS tokens defined |

### Key Gaps to Address
- Analytics charts use **MOCK data** (not real DB queries)
- Playground AIChat is **mocked** (SSE endpoint exists but client doesn't use it)
- No **real-time CLI ↔ Dashboard sync** (no WebSocket infrastructure)
- Sidebar links to **dashboard/keys** and **dashboard/playground** but those routes don't exist
- **Collections, Followers, Achievements** are empty placeholders
- No **team workspace** views (orgs exist but no team dashboard)
- No **version diff visualization** on package pages

## Verification Plan

After each phase, verify:

1. **Phase 1**: Run `pnpm build` — all packages compile. Run `pnpm test` — all tests pass. Manual: `skillspace link` pairs CLI to dashboard, `skillspace dashboard` opens browser, dashboard activity feed shows CLI events, playground streams real AI responses, analytics charts show real data.
2. **Phase 2**: Dashboard overview loads with real stats. Per-skill analytics page shows charts. Version diff renders between two versions. Export produces valid CSV.
3. **Phase 3**: Create org, invite member, assign role. Capability stack pins skill versions. `skillspace install --team <org>` installs pinned versions. Audit log tracks actions. Notifications appear in bell.
4. **Phase 4**: Create collection, add skills, install via CLI. Post discussion on skill page. Submit showcase entry. Author profile shows reputation score.
5. **Phase 5**: Recommendations appear on package pages. Pipeline composes two skills. Memory persists across REPL sessions. `skillspace author` generates valid YAML.
6. **Phase 6**: `docker compose up` starts self-hosted registry. SSO login works. TypeScript SDK `import { SkillSpace } from '@skillspace/sdk'` works. GitHub Action validates a skill in CI.
